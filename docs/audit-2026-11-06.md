# Function and design audit, 2026-11-06

**Method.** Playwright and axe-core (WCAG 2 A/AA plus best practice) over 22 public pages at 1280px and 390px, light and dark (70 page views), plus a seeded contest viewed as voter, entrant, organizer and judge (16 more). A crawl of all 409 internal links, and direct checks of endpoints, headers, robots, sitemap and error pages. Run against the local site.

## Fixed in this pass
| Gap | Fix |
|---|---|
| `/contest-enter` opened without a contest crashed ("Cannot read properties of undefined"), with no heading or main landmark | Shows "We can't find that contest" with a link back; the page text is in `<main>`; added a description |
| First field of the contest wizard (`#f-name`) had no label (critical) | `aria-label` ("Contest name"); `input()` in `addflow.js` accepts `aria` |
| The add flows' step bar (progress and back/next) sat outside any landmark (all three add pages) | `role="navigation"` with a label |
| Map tab "Places" had a name that did not contain its visible text (WCAG 2.5.3) | Removed the `aria-label`; the visible text names it |
| Offline page text was too faint in dark mode (contrast 2:1) | Text colour now follows the theme |
| "Open in Google/Apple Maps" route buttons failed contrast on contest pages (light 2.2:1), caused by an older rule that forced dark text | White text on a darker shade of the season colour; dark mode keeps the light button with dark text; checkboxes are 24px |
| `/in/<unknown city>` gave a bare plain-text 404 | Styled "No upcoming events in that city yet" page with links |
| `/api/<unknown>` gave an HTML 404 | JSON 404 (`functions/api/[[path]].js`) |
| `/add-contest` and `/contest-enter` had no meta description | Added |

## Found, not fixed (needs a decision or is out of reach)
- **No Content-Security-Policy header.** The site sends the other security headers (frame, referrer, nosniff, permissions) but no CSP. The map (MapLibre, unpkg, OpenFreeMap), Google Fonts, Turnstile, Google sign-in and Stripe all need allowing, so it should start as `Content-Security-Policy-Report-Only` and be tightened after a week of reports. Owner decision.
- **Two visual styles.** Server-built pages (Help Center, city pages, installer and event pages) use a cream background and a heavier heading style; the app pages are white. Unifying them is a restyle of `functions/_lib/shell.js`, not a bug fix.
- **`/c/<unknown slug>` returns HTTP 200** with an on-page "not found" (the page is a static shell). Harmless for visitors (`/c/` is disallowed in robots.txt), but a real 404 needs a Function on that route.
- **Skip link on `/tutorials`** is flagged by axe as outside a landmark. It is a known false positive for skip links.
- **`/api/events` is about 890 KB before compression.** Cloudflare compresses it and it is cached with an ETag, so it is fine today; a bounding-box or tile API would help if the data grows.
- **Privacy page says "We do not show ads."** That must change before any paid banner ships.
