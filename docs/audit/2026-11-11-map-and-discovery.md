# Audit: map and discovery (2026-11-11)

Scope: home `/`, map, search, filters, list and bottom sheet, place cards, `/e/<id>`, `/in/<city>`, Favorites, Route these, sponsor banner, Ask SoCal Lights button, offline, first visit, share/SEO tags. Read-only; no product code changed.

Method: Playwright (Chromium) against the live site, anonymous GET browsing only (no sign-in, no form submitted, no verification clicked). Heart and Route actions only used the browser's own local storage. Viewports: iPhone 17 Pro Max (440x956, DPR 3, touch), 360x640, 320x568, desktop 1440x900; light and dark; offline reload; throttled network (400 ms latency, about 50 KB/s). Tags in the table: **T** = confirmed by testing, **C** = from reading code only. Screenshots are in `docs/audit/screens/map/`.

Not tested (say so rather than guess): any signed-in flow; granting location (Find my location result, "Near" with a city); the Apple/Google/Waze picker beyond the Apple Maps default; the Filters dialog focus trap; real 200% text zoom (I tested 320 px reflow instead); tablet; the installed/app-wrapper behavior; visual rendering of `/in/<city>`.

## Summary: top 10 issues

1. MAP-01 (P1): the red Ask SoCal Lights button sits on top of primary actions: "Show 952 places" in Filters, "Directions" on a place card, "Share" on the event page, the Sort control on the list.
2. MAP-02 (P1): the Route sheet says `aria-modal="true"` but keyboard focus leaves it after 6 Tab presses and walks the whole page behind it; the chat button also stays above the dimmed backdrop.
3. MAP-03 (P1): first visit opens on all of California (Fresno to Ensenada) with cluster blobs, no "near me" prompt, and the list is labelled Nearest but starts in Dana Point and Laguna Beach.
4. MAP-04 (P2): on opening Favorites, the "Use my location / No thanks" popup lands on top of the Route these and Start controls.
5. MAP-05 (P2): on 360x640 and 320x568 phones the bottom tab bar and chat button hide the Sort control and cut the count ("950" without "places").
6. MAP-06 (P2): map controls are 40x40 and the sheet grab handle is 27 px tall; Route these is 40 px.
7. MAP-07 (P2): the sponsor banner clips its own text mid-word on every viewport and its call and "Advertise here" links are 24 px tall inside a moving strip.
8. MAP-12 (P2): event page title is cut mid-phrase ("Parade of Lights Premier Viewing at the… | SoCal Lights"), the share image is a hotlinked third-party photo with no size or twitter:image.
9. MAP-11 (P2): the same list shows four different counts (952, 944, 935, 950) with no label saying which is "in view".
10. MAP-08 (P2, from code): cards use "Home display" and "<season> display", against the product word "home".

## What already works well

- Skip link to the list, labelled search combobox with a suggestions list ("Dana Point - Show this city on the map" then events), and a clear empty state ("No places match “zzzzqq”. Clear search").
- Filters is a labelled modal dialog that takes focus; When, Near, County, Cost and Type are all there.
- Contrast measured: body meta 5.41:1, tags 4.67 to 5.0:1, main text 18:1. Dark mode is consistent.
- No horizontal scroll at 320 px; hearts and share are 44x44; `aria-pressed` on hearts.
- Offline reload of `/` still showed the list. The first list item appeared at about 11.5 s on the throttled connection.
- Route sheet copy is clear, including the iOS 18.4 note for Apple Maps.
- SEO basics: canonical, titles, descriptions, Event and Breadcrumb structured data on `/e/` and `/in/`, 404 with `noindex` for a missing event, sitemap and robots present.
