# Security audit, SoCalLights.app (2026-11-07)

Scope: `main` at 668b381 (read-only), a local `wrangler pages dev` instance with a local D1 (DEV_AUTH, no external calls), and GET-only requests to https://socallights.app and https://socal-lights.pages.dev (headers and public JSON only; nothing written, no emails, no payments, no brute force). Builds on `docs/audit/2026-11-04/security.md`; items below are labelled **FIXED** (verified in code, and live or locally where stated), **OPEN** (still true), or **NEW**. Not exercised: real Stripe, real email, the Cloudflare dashboard (Access cookie SameSite, WAF rules, Pages preview bindings, D1 quotas) and the real geocoders.

## Top 5

1. **S-07 (Medium, OPEN, now reproduced): email sign-in code attempts are not limited under parallel requests.** 60 parallel wrong guesses against one live code: 26 were evaluated (limit is 5). No per-IP limit on verify. Account takeover is a numbers game, but every account (installer owners who can pay, organizers) is exposed.
2. **N-01 (Medium, NEW): `/api/events` cache is bypassed by any query string, and `?all=1` is public and never cached.** Each such request reads the whole events table and returns 1.3 MB. About 1,800 requests exhaust D1's free 5M-rows-read/day and take down every page.
3. **S-04 (Medium, OPEN): any signed-in account can attach itself to an existing installer profile** (case-insensitive name match), fill its blank website/phone/area/email, and then claim it by "email matches website". Quote leads (customer name, email, phone) go to `owner_email || email`.
4. **N-02 (Medium, NEW): any account can publish an official-sounding contest ("City of Irvine Official Lights") that goes live on the public map at once, then add up to 500 arbitrary street addresses as "approved entries" with a free-text name.** Confirmed locally: the contest appeared in `/api/events` immediately. Harassment, impersonation and a doxxing-style vector; the only brake is an admin note that nobody is alerted to.
5. **S-02 (Medium, OPEN): still no Content-Security-Policy, not even Report-Only, and no HSTS header.** Four other headers are now on every response (FIXED). With CSP absent, any future XSS is unconstrained, and admin pages load third-party scripts.

Nothing found needs action tonight. No Critical or High findings.

## Authorization and abuse checks on the new surface (all passed unless listed above)

- **Stripe webhook** (`api/stripe-webhook.js`, `_lib/featured.js:59`): HMAC-SHA256 with constant-time compare, 300 s timestamp tolerance, event-id dedupe stored only after success, `INSERT OR IGNORE` orders and an `applied` flag guard replay and concurrency, refund/dispute-before-payment handled. Unsigned and bad-signature requests return 400 locally. Amount mismatches are flagged, not applied silently wrong. No finding.
- **Checkouts** (`feature/checkout.js`, `sponsor/checkout.js`): `sameOrigin` + signed-in + ownership (`ownsEvent`, `ownsInstaller` exact match), prices from the server, same error for "not found" and "not yours", per-account cap 6 an hour and 20 a day (`checkoutLimit`), idempotency key hashed with the user id, success/cancel URLs built from the request origin, email from the account. Weak point is upstream: ownership of an installer profile (S-04).
- **Event claims** (`me/claims.js`): auto-approval needs a non-free-mail domain that matches the event's site and is not an aggregator; 5 pending and 10 a day caps. A claim only allows paying for placement.
- **Organizer-added entries**: staff-only (403 for another account, 401 anonymous, 403 cross-origin, tested locally), blocked once results are announced or voting has begun, 10 calls an hour per account with a log. Abuse path is N-02.
- **Creator unpublish / home edit** (`me/homes/[id].js`): ownership by `user_id` or the contact email (which is always the account email); delete only by the poster; installer owner can edit but not delete. 404 for others.
- **IDOR**: `contests/<slug>/manage|export|votes|stats` return 404 to a non-staff account; sponsor and claims queries scoped to the signed-in user.
- **Unauthenticated endpoints**: `visit` caps page names per day (80) and per key (20,000); `banner/hit` only counts currently sponsored installers; `report` and `help/contact` shared 5 an hour per IP (tested: 4 of 8 blocked after the first 4 locally, then 429); events detail and `/e/` validated above. Write-volume risk is N-04.
- **SSRF**: geocoder URLs are fixed hosts with `encodeURIComponent` queries (`util.js` census and Nominatim, `address.js` Geoapify); the only fetch of a user-influenced URL is the event verifier (`_lib/events.js`, not changed since Nov 4).
- **Tokens**: unsubscribe tokens are 18 random bytes (hex), checked by regex and DB lookup; alert tokens are two UUID-derived ids; installer-confirm tokens likewise; sessions are 32 random bytes stored hashed. Cookies: `HttpOnly; SameSite=Lax; Secure` (https). Cron comparisons use `!==` (Info, not constant time).
- **Secrets scan**: patterns for Stripe, Resend, AWS, GitHub, Google, Cloudflare tokens, private keys across the tree (1,150 tracked files) and deleted key files in history: no matches except documented placeholders and test fakes (`tests/_pay.mjs`). `.dev.vars` is ignored. Wrangler config contains only the Access team domain and AUD (public identifiers) and the Turnstile site key. `/.git/config`, `/wrangler.toml`, `/migrations/*`, `/_tmp_dummy` return 404 live.
- **Tests**: `npm test` 177 of 177 passing; `npm audit --omit=dev` 0.

## Suggested order

1. S-07 atomic attempts plus per-IP verify limit (small, closes the real account-takeover path).
2. N-01 cache key whitelist and admin-only `all=1`, plus one Cloudflare rate-limit rule.
3. N-02 and S-04 together (contest review hold, organizer-added home cap, installer linking rules).
4. N-03 and S-10 email caps (reuse `reserveSends`).
5. S-02 CSP Report-Only and HSTS; S-08 admin same-origin; N-06 CODEOWNERS or gate from `main`.
6. Owner dashboard checks: Access cookie SameSite, preview deployment bindings, D1 usage, WAF rate-limit rule.
