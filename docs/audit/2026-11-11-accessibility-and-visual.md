# Accessibility and visual consistency audit, 2026-11-11

Scope: every public page of https://socallights.app (anonymous GET and navigation only; nothing submitted, no sign-in, no Turnstile click) against `origin/main` at 9497b08. Read-only: no product code changed.

Method: Playwright 1.x with system Chrome and axe-core 4.10.2 (tags wcag2a, 2aa, 21a, 21aa, 22aa, best-practice) on **35 URLs x 4 viewports (iPhone 17 Pro Max 440x956 @3x, 360x640, tablet 820x1180, desktop 1440x900) x light and dark = 280 runs** (1 run errored: `/remove-home` desktop light, blocked by the page's CSP when axe was injected). Dark mode was forced both by `colorScheme` emulation and by setting `data-theme`. All six season accents were applied on the map (`data-season`) in light and dark, with the Filters path attempted. Extra probes: keyboard tab order and focus indicators on 13 pages, computed font sizes, labels, landmarks, heading order, tap targets, input border and placeholder contrast, reflow at 320 and 256 CSS px, a long-word injection test, 404, offline, and code reading of `public/*.css`, `functions/_lib/shell.js`, `helpui.js`. Raw JSON was kept outside the repo.

Pages covered: `/`, `/pricing`, `/help`, `/help/find-lights-near-me`, `/tutorials`, `/terms`, `/privacy`, `/contests` (and `/archive`, which redirects to `/contests#past`), `/add`, `/add-event`, `/add-house`, `/add-contest`, `/feature`, `/sponsor`, `/partner`, `/past`, `/in`, `/in/los-angeles`, `/e/alhambra-lny`, `/installer/lights-up-today`, 404 (`/zz-nope`), `/offline.html`, `/unsubscribe`, `/prefs`, `/contest-pass`, `/cancel-renewal`, `/remove-home`, `/home-photos`, `/sponsor-invite`, `/profile`, `/organizer`, `/judge`, `/contest-enter`, `/installer-manage` (the last six showed their signed-out state only). Not testable here: `/past/<slug>` (no finished contest is published: the live `/past` says "Results of 0 finished contests") and `/c/<slug>` pages (disallowed and none found in the sitemap).

Owner-accepted items, not reported: the small red "Ask SoCal Lights" circle at bottom right on phones, keyboard focus leaving the Route sheet, first visit opening zoomed out on California with the "Nearest" list.

## Summary (top 10)

1. **Remove-my-home form is unreadable in dark mode (P1).** Typed text in "Which home?" is #f5f3ee on a white box, 1.1:1 (A11-01). A person asking to take their home down cannot see what they type.
2. **"Founder city" tag fails contrast in dark mode (P1).** #2559b8 on #161a22 is 2.65:1 (needs 4.5:1) on `/contests` (and the same class is used on the contest and organizer pages) (A11-02).
3. **Both bugs share one root cause:** the add-flow stylesheet (`addflow.css`) defines `--tile` and `--bg` but not `--surface` or `--ice`, so pages built on it fall back to light-mode hex values in dark mode. Fix once in `addflow.css` (A11-01, A11-02).
4. `/contests` does not reflow at 320 CSS px (400% zoom of a 1280 window): 34 px of horizontal scroll, "Past results" tab and card edge cut off (A11-03, WCAG 1.4.10).
5. Inputs under 16 px (iOS zoom on focus): map sort select 14 px; the Help "Ask us" textarea and email 14 px (A11-04).
6. Text-field borders are 1.28:1 (light) and 1.32 to 1.47:1 (dark) on the Help search, Help "Ask us" and the "Weekly email" boxes on every city and event page; WCAG 1.4.11 asks for 3:1 (A11-05). Default placeholders in dark are 3.78 to 4.22:1 (A11-06).
7. **Three different page headers** (title-only 61 px, logo+Map 88 px, logo+Map+breadcrumb 72 px) plus a header-less 404 and offline page (A11-07). Three slightly different "Christmas red" hex values and two sets of greys across stylesheets (A11-08).
8. "Display" wording is still live in user-facing text the owner replaced with "home": 404, Pricing, add-home gate, `/add` description (A11-09). `/past` says "Results of 0 finished home decorating contests" (A11-10).
9. Skip link is missing on `/contests`, `/add-event`, `/add-house` and the 404 page, while the other pages have one (A11-11).
10. What passes: axe found **no violation on 33 of 35 pages in all 8 viewport/theme combinations**, no horizontal overflow at 360 to 1440, all six season accents pass on the map, `tests/asset-versions.test.mjs` is green (3 of 3).

## Not tested or limited

- Forced-colors and `prefers-contrast` emulation: not run. RTL: not run. Real screen readers and devices: not run.
- Print: the printable posters need a signed-in organizer; code read only.
- 200% text zoom: 320 CSS px reflow was tested on 20 pages; 256 px (extreme) shows small overflow on `/tutorials` (10 px), `/feature` (8), a city page (15, a tag), offline (26): ignore unless wanted.
- Local `npm run dev` was not used; all pages in scope are served the same way live.
- The axe contrast check cannot judge text over the map or photos; the map search placeholder is a translucent pill over map tiles and was not measured pixel by pixel.
- Fixed since the 2026-11-07 audit and re-verified: search focus ring (A1), device dark setting (A4: the theme script now honors `prefers-color-scheme`), 404 and offline now use Plus Jakarta Sans, `/in/*` city pages have breadcrumbs.

## What works well

- Zero axe violations on 33 of 35 URLs in 8 combinations; no horizontal overflow at 360, 440, 820 and 1440 in light or dark.
- Cache-busting is consistent: `tests/asset-versions.test.mjs` passes (one `?v=` per asset, none missing).
- Every sampled tab stop shows a changed style, tab order follows reading order, skip link present on most pages, one `<main>` and one `<h1>` per page, no heading jumps, no unlabeled visible inputs on app pages (the honeypot is `aria-hidden` and `tabindex=-1`), no empty links or buttons, live regions on dynamic areas.
- Season palette: all six accents pass as button fills and chips in both themes; status tags carry icons.
- Honeypots, `lang="en"`, viewport meta (no zoom lock), 16 px+ inputs on the add flows, 48 px primary buttons.
- 404 page is a real, friendly page with a way back.
