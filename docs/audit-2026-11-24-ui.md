# UI audit, 2026-11-24

Scope: public site, add flows, profile, Admin. Run locally (wrangler pages dev, port 8792) and driven with Chromium (Playwright). About 330 screenshots at 360x740, 390x844, 844x390, 768x1024, 1024x768, 1280x800 and 1440x900, light and dark. Nothing in the product was changed; seeded rows (a user, two homes, two event submissions, an order, a claim, a contest) are in the LOCAL database only.

Screenshot folder (S): `/tmp/claude-0/-home-user-socal-lights-app/d914bc85-b7f6-567f-9057-ecf95841d4b3/scratchpad/ui-audit/`
Every path below is S + the file name, written out in full where it matters.

Method notes. "Measured" = a script read the DOM (bounding boxes, computed font size, computed colors). "Seen" = I looked at the PNG. Contrast figures came from computed colors on solid backgrounds only; text on photos is "not verified". Full-page screenshots draw fixed bars (bottom tab bars, sticky Save bars) in the middle of the page; I did not count those as bugs. Items already fixed per docs/status.md (day/night rule, details action bar on iPhone, Admin phone bottom bar, pulsing pins, video first slide, Save/Cancel spacing) are not re-reported.

No page had horizontal page scroll in any layout (about 270 measured shots). Body text is 12px or larger everywhere except one 10px "Featured" label. Reduced motion is respected (pin rings and marquee have animation none). The skip link works. These are in "what already looks good".

## 1. Executive summary: the 10 worst problems

1. **Event details are about 44px wider than a 360 phone and 14px wider than a 390 phone (P0).** The hero, photo credit, next arrow, chips and the When/Cost cards run off the right edge; the title collides with the "1 / 4" counter. Measured: `.detail` is 328px but `.hero` is 404px at 360 wide, and 404px at 390 too. Seen: `S/phone-small-light-event-details.png`, `S/phone-light-event-details.png`.
2. **Phone list sheet: the Places/heart/bag pill floats over the list with no backing, cutting card titles (P1).** `S/phone-light-home-sheet-half.png` ("Viewing at the Ocean Institute" is sliced by the pill).
3. **Admin side menu on a 1280x800 laptop shows 12 of 25 items; "Help Center" is cut in half and Money, Marketing and System are out of sight with no scroll cue (P1).** `S/laptop-dark-admin-dashboard.png`.
4. **Add-event, add-home and add-contest on a laptop: the live Preview card runs past the right edge (right = 1310 on a 1280 screen), and its caption is cut (P1).** `S/laptop-light-add-event-1.png`.
5. **Wizard progress bar lies: 6 segments for "Step N of 7" (and "of 9" for homes) (P1).** `S/phone-small-light-ev-step6.png` shows step 6 of 7 with 4 of 6 segments filled.
6. **Tab rows are cut off with no fade or arrow: Pricing audience tabs on phones (Contest organizers and Installers hidden), Admin Events ("Paid placem"), Orders ("Refunded and dispute"), Ads (P1).** `S/phone-light-pricing.png`, `S/phone-light-admin-events.png`, `S/phone-light-admin-orders.png`, `S/phone-dark-admin-ads.png`.
7. **Admin phone lists use 20px-high text links ("Open", "Edit", "View card") and 20px checkboxes; 10 to 18 undersized targets per screen (P1).** `S/phone-light-admin-users.png`, `S/phone-light-admin-events.png`.
8. **Phone landscape (844x390): header, sponsor strip, tabs and filter chips use about 55% of the height, so the list shows about one card (P1).** `S/phone-landscape-light-home.png`.
9. **Admin Orders table on tablet portrait clips the Status column ("Not app...") with no horizontal scroll cue (P1).** `S/tablet-portrait-light-admin-orders.png`.
10. **Home details with no photos show a 40%-of-screen empty blue "No photos yet" box above the title (P2).** `S/phone-light-home-details.png`.

### 2.1 Phone small, 360x740

**Map home** (`S/phone-small-light-home.png`, `S/phone-small-dark-home.png`)

## 3. Cross-layout consistency

- **Header buttons.** On info pages the "Map" button is a white pill with a drop shadow, next to outlined 44px circle buttons (theme, profile). On the map home all header buttons are filled circles. Pick one style. `S/phone-light-profile-top.png`, `S/phone-small-light-contests.png`.
- **Sort select vs chips vs tabs.** Three different "choose" controls: brown-filled select, outlined chips, gray segmented tabs. One shared token set for neutral controls would remove the mismatch (F22).
- **Tab rows.** Pricing, Admin Events, Orders, Ads all use a scrolling tab row with no scroll cue (F6); build one shared `.tabs` component with a fade and snap.
- **Tap targets.** Public pages mostly meet 44px for primary buttons but not for text links, sponsor strip, header Help, map markers (34px). Admin lists are below target on phones (F15, F20).
- **"Optional" and error use the same red** (F3 note).
- **Dates.** Mostly Month/Day/Year. Exceptions found: Cloudflare usage page ISO dates (F18); the home card photo badge uses "Dec 1 only" while the text line uses "Tue, Dec 1, 2026" (two formats on one card).
- **Progress UI.** Wizard bar and "Step N of M" come from different numbers (F3).
- **Footer.** Shown inside wizards and sign-in gates where it competes with the sticky action bar.
- **Focus styles.** Most controls use a 2px light-blue outline; MapLibre zoom buttons use MapLibre's own blue box-shadow; the search input has no outline of its own (F19).

## 4. Accessibility

- Measured contrast failures: only one on solid backgrounds, the dark Claim page link at 2.8:1 (F30). Text over photos (photo credit, "1 / 4" counter, hero kicker) was flagged by my script at about 1:1, but that is the script not seeing the image; not verified. Fix suggestion regardless: put a 50% black pill behind the counter like the credit already has.
- Keyboard: tab order on the home page is skip link, brand, search, season, theme, account, add, menu, Route these, map canvas, featured pins, zoom buttons, locate, attribution. The list of results comes after the whole map. The skip link ("Skip to the list") covers this; good. Focus rings are visible (2px, 143,176,255 on dark) on every button tested.
- F19 `#q` (search) computed `outline:none` and no box-shadow on the input itself. It may draw a ring on its wrapper; I did not confirm it visually. Check, and add `:focus-within` ring to the pill if it does not.
- Icon-only buttons have aria-labels (checked in the focus sequence). The Admin rail badges have no text (F16).
- Reduced motion: respected for pin rings and the sponsor marquee.
- Tap targets: see F15, F20.
- Zoom: I did not test 200% browser zoom or text-size scaling. Not verified.

## 5. What already looks good

- No horizontal page scroll anywhere; layouts reflow cleanly from 360 to 1440.
- The map home first screen on phone and desktop: clear hierarchy (search, filters, one list), and the gold star pins stand out without hiding the map.
- Event cards: photo, date badge, title, place, price/confirmed chips are consistent in light and dark.
- Season menu: clear states ("On now", "Nothing listed yet").
- Wizard steps are one question per screen with large inputs, good helper text and a good inline error state.
- Add-house "Who's posting?" option cards: large targets, obvious selected state.
- Contest page header card and entry/vote chips are clear; empty state ("No homes yet") explains what to do.

- Admin dark/light parity is good; Approve/Decline and Publish/Reject pairs are clear.
- Admin phone: stat cards and result counts ("3 results") read well.
- Skip link, aria-labels on icon buttons, reduced motion.
